# [INDUSTRIAL_PRD] 业务需求文档

## 1. 执行摘要

### 1.1 产品愿景
为18-25岁年轻人提供一个极简、无干扰的社交媒体平台，核心功能为发布图文动态、单向关注好友以及按时间倒序浏览内容。V1版本只验证「关注+浏览」这一核心闭环，不做社交互动（点赞、评论、私信）和个性化推荐，打造「轻语录」——一个只关乎内容本身的轻量社交体验。

### 1.2 成功指标（KPI）
- **指标1**：首周用户留存率 > 20%
- **指标2**：时间线页面加载延迟 < 500ms（不含图片资源）
- **指标3**：完成注册→发布首条动态的转化率 > 60%

## 2. 用户画像与场景

### 2.1 主要用户画像：Z世代轻社交用户
- **目标**：快速浏览关注好友的日常动态，用最少的操作发布图文内容，不被算法和社交压力裹挟。
- **痛点**：现有平台充斥着算法推荐、广告、评论点赞攀比和多图视频加载压力；需要一个小而美的空间只关注朋友的真实内容。

### 2.2 关键用户场景
- **场景A — 注册与首次体验**：用户通过邮箱/手机号接收验证码 → 设置用户名+密码 → 登录系统 → 系统默认无关注用户时展示「发现用户」列表 → 用户关注至少1人 → 时间线开始展示内容。
- **场景B — 发布图文动态**：用户在首页点击发布按钮 → 输入纯文字（最多280字符） → 可选上传1张图片（本地文件选择，非多图） → 点击发布 → 动态出现在关注者的时间线中。
- **场景C — 浏览时间线**：用户登录后进入首页 → 系统查询该用户关注的所有用户 → 按发布时间倒序（最新在前）拉取动态列表 → 用户可无限滚动浏览 → 无算法干预、无广告插入。

| FR-01 | 注册与验证 | 用户通过邮箱或手机号接收验证码完成注册；支持用户名+密码+验证码流程；禁止免验证注册 | P0 |

## 4. 业务规则与逻辑

- **规则1**：动态最大字符数为280字（含标点符号和空格）。
- **规则2**：每篇动态最多附带1张图片；不允许上传视频、多图或嵌入外部链接。
- **规则3**：图片上传仅支持 JPEG/PNG 格式；单文件大小限制 ≤ 5MB。
- **规则4**：图片存储路径为本地文件系统（如 `uploads/` 目录）；禁止使用云存储（OSS/S3/CDN）。
- **规则5**：关注关系为单向模型；用户A关注用户B时，B无需确认，A自动在时间线看到B的动态；不存在「双向好友」概念。
- **规则6**：时间线排序规则固定为 `SELECT * FROM posts WHERE author_id IN (关注用户ID列表) ORDER BY created_at DESC`；禁止任何算法干预。
- **规则7**：注册必须经过邮箱或手机验证码验证；禁止免验证直接注册。
- **规则8**：密码存储使用 bcrypt 哈希；禁止明文存储密码。

## 5. 非功能需求

- **性能**：单容器部署，支持 ≤ 1000 CCU（并发用户数）；不设计分库分表；时间线查询延迟 < 200ms（缓存优化）。
- **安全性**：密码使用 bcrypt 哈希；验证码有效期5分钟；防止暴力登录（同一IP 5次失败后锁定15分钟）；基本的XSS/CSRF防护。
- **可用性**：支持桌面端和移动端浏览器访问；响应式布局；图片懒加载；注册流程不超过3步。

## 6. 业务风险与缓解措施

| 风险 | 缓解措施 |
| :--- | :--- |
| **风险1**：用户发布违规内容（敏感图片/文字） | MVP阶段依赖人工举报+管理后台删除功能；内容量小可人工审核；不实现自动内容过滤 |
| **风险2**：用户留存率不达标 | MVP核心假设为「轻社交」模式是否能吸引用户；若留存不足则在V2考虑增加评论/点赞等互动功能 |
| **风险3**：验证码发送成本（邮件/SMS API费用） | MVP阶段使用邮件验证码（低成本）；若使用短信则按量付费；初始用户少成本可控 |

## 7. 范围边界与功能限制规范

本部分将《边界宣言》中的出界决定翻译为具体的架构与代码功能限制规范，供 Code Reviewer 审计评估。

### 🚫 媒体处理限制
- 禁止设计/开发任何处理视频上传、视频播放、视频转码的 API 接口。
- 禁止实现多图上传（单次上传 >1 张图片）的逻辑。
- 禁止实现图片裁剪、滤镜、编辑功能。
- 禁止实现任何连接云存储（OSS/S3/CDN）的文件上传代码；图片存储仅限本地文件系统。
- 数据库结构禁止包含 `video_url`、`multi_images` 等相关字段。
- **BANNED IMPLEMENTATION KEYWORDS**: `UploadVideo`, `VideoFile`, `MultiImageUpload`, `ImageEditor`, `OSS`, `S3`, `CDN`, `ImageCropper`, `FileCompressor`

### 🚫 社交互动限制
- 禁止设计/开发任何处理点赞（Like）、评论（Comment）、分享（Share）的 API 接口。
- 数据库结构绝对禁止包含 `likes`、`comments`、`shares` 相关的表。
- 禁止实现双向好友关系（Friendship/MutualFollow）逻辑。
- 禁止实现私信/聊天（DM/Chat/Message）的 WebSocket 或 REST 接口。
- 禁止实现通知（Notification）系统。
- 主路由禁止注册 `/api/like`、`/api/comment`、`/api/message` 等相关 Endpoint。
- **BANNED IMPLEMENTATION KEYWORDS**: `Like`, `Comment`, `Share`, `Friendship`, `MutualFollow`, `DM`, `Chat`, `Message`, `Notification`

### 🚫 推荐算法限制
- 禁止实现任何基于机器学习的推荐模型、协同过滤、内容标签权重排序逻辑。
- 禁止实现用户行为追踪（浏览时长、点击率）用于推荐模型训练。
- 时间线排序逻辑仅限 SQL 查询：`SELECT * FROM posts WHERE author_id IN (followed_ids) ORDER BY created_at DESC`
- 数据库结构禁止包含 `user_score`、`content_weight`、`personalized_rank` 等字段。
- **BANNED IMPLEMENTATION KEYWORDS**: `RecommendationModel`, `MLRecommender`, `CollaborativeFiltering`, `UserScore`, `PersonalizedRanking`, `TrendingAlgorithm`

### 🚫 用户与注册限制
- 禁止实现免验证注册（必须走邮箱/手机验证码流程）。
- 禁止实现 OAuth 第三方登录（微信/Google/GitHub）。V1 仅支持邮箱/手机+验证码注册。
- 禁止实现密码找回/重置功能（推迟至V2）。
- 主路由禁止注册 `/api/auth/oauth`、`/api/auth/reset-password` 等相关 Endpoint。
- **BANNED IMPLEMENTATION KEYWORDS**: `OAuthLogin`, `SocialLogin`, `PasswordReset`, `NoVerificationRegistration`
