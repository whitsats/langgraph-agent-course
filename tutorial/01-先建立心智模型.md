# 第 01 章：先建立心智模型

## 本章目标

1. 说清"智能体"和"聊天机器人"的区别到底在哪一层
2. 记住一张全局地图：五块拼图，以及你已有的技能各对应哪一块
3. 知道这一套东西的分层（LangGraph / LangChain / Deep Agents），以及**为什么必须从中间层学**

---

## 概念：智能体 = 会自己决定"下一步做什么"的程序

先看三个东西的区别，用你熟悉的话说：

| 你写过的东西 | 类比 | 关键差异 |
|---|---|---|
| 调一次 LLM API，把结果返回给前端 | 一个**函数** | 输入 → 输出，一次完事 |
| 多轮对话（带历史） | 一个有**会话状态**的接口 | 还是会说话，不会做事 |
| 智能体 | 一个**会自己调内部接口的接口** | 它可以决定"我现在要调用 `get_weather`" |

区别就在**工具调用（tool calling）**这一层。模型不只是吐文字，它可以输出一个结构化的请求：

```
我需要调用 get_weather，参数 {city: "上海"}
```

你的代码执行这个函数，把结果回灌给模型，模型再决定下一步。**这个"决定 → 执行 → 回灌 → 再决定"的循环，就叫 Agent Loop。**整个智能体开发，80% 的功夫都花在让这个循环可靠、可控、可观测上——而这正是"框架知识"之外的真本事。

所以后面所有内容你都可以放回这句话里：**框架帮你管的是循环里的状态、分发、终止和持久化。**

---

## 概念：五块拼图（先知道边界在哪）

| # | 拼图 | 解决什么 | 你会先学到的 |
|---|---|---|---|
| 1 | **Loop** | 模型怎么决定调工具、结果怎么回灌、什么时候停 | 第 03 章手写一遍 |
| 2 | **工具与交付** | 让模型能干活，并且按你要的格式交结果 | 04 章（`@tool` / 结构化输出） |
| 3 | **编排（状态机）** | 多步骤流程、分支、重试、断点续跑、人工卡点 | 05–07 章（LangGraph） |
| 4 | **知识与工具生态** | 内部资料（RAG）、别人的工具（MCP） | 08–10 章 |
| 5 | **工程化** | 评测、trace、上下文、安全、部署 | 11 章 |

**只学第 2 块（怎么调 API、怎么写 prompt）的人，做出来的是 demo；把 3、5 块补上，才叫能交付。**

---

## 概念：分层——为什么从中间层学

官方自己把这套东西分成三层，这不是营销词，是**排障地图**：

| 层 | 提供什么 | 代表 |
|---|---|---|
| Runtime（运行时） | 持久执行、流式、人机协同、底层控制 | **LangGraph** |
| Framework（框架） | 抽象与集成：agent loop、中间件、结构化输出 | **LangChain**（建在 LangGraph 上） |
| Harness（马具/脚手架） | 预制工具、提示词、子智能体、文件系统、Token 管理 | Deep Agents SDK 等 |

**为什么要懂这个分层？** 因为出问题时你得知道去哪一层修：

- 状态没存住、流程跑飞了 → 是 **LangGraph** 层的事
- 模型输出格式不对、工具没被调用 → 是 **LangChain** 层的事
- 提示词啰嗦、任务拆得不好 → 是 **Harness** 层的事

只学最上层（"用某某 SDK 一键生成一个 agent"），出错时你完全没有抓手。本教程的主线是 **LangGraph（机制）+ LangChain（模型与工具）**，Harness 只在第 10 章带你认个门。

---

## 概念：你的存量技能 → 智能体概念

这是本教程给你的最大便利。你几乎每项技能都有对应物：

| 你已经会的 | 对应到 | 相似到什么程度 |
|---|---|---|
| Redux / Vuex 的 reducer | **reducer**（状态合并函数） | 几乎是同一个东西：`(当前值, 更新) => 新值` |
| Express / Laravel 中间件 | **Middleware** | 同名同概念，都是"链式钩子" |
| 登录 session / `session_id` | **`thread_id`** | 完全对应，多用户隔离就靠它 |
| Laravel Queue + Horizon | **checkpointer 的持久执行** | 你要的"任务持久化 + 断点续跑"，它内置了 |
| `JSON.parse` / Zod schema | **Pydantic + 结构化输出** | 目的是同一个：别信任自由文本 |
| `Promise.all` | **`asyncio.gather`** | 一样，注意 Python 是 `asyncio` |
| `npm` / `composer` | **`uv`** | 见第 00 章 |
| Nginx 反代到后端服务 | **网关 / Base URL 切换** | 换模型供应商就是改一行配置 |

**同时要警惕反向迁移**——有几条肌肉记忆会让你摔跤，先记下来：

1. **"我要自己搭持久化"**：Laravel 里你习惯了 Queue + Redis；这里 checkpointer 已经做了，别再写一套。
2. **"拿到文本就正则解析"**：自然语言不是 JSON，用结构化输出（第 04 章）。
3. **"节点要拆小、函数要单一"**：别把 agent 图拆成十几个节点，每个节点都要过一次模型，又慢又贵。**一个节点 = 一个决策**，不是"一个函数"。
4. **"数据库就该上 ORM"**：结构化数据用 SQL / Text2SQL，不要什么都向量化（第 08 章会讲该不该建知识库）。

## 跟着做

本章没有代码，做三件准备：

1. 按第 00 章把环境跑起来，看到 `✅ 会调用工具`。
2. 打开 `../LEARNING_PLAN.md`，只看两张表：**§1.1 表面积矩阵**（哪些必学、哪些知道就行、哪些明确不做）和 **§2 存量技能映射**。
3. 建一个 `notes.md`，写下你最想做的那个智能体是什么（一句话即可）。后面每章结束都回来补一句"这一章对我要做的东西有帮助吗"。

**为什么要写这个文件？** 因为你很容易滑进"把教程读完"的模式。有目标物在手，你会自然地跳过不需要的东西——这正是你上周批评我"完整度不够"的反面：**完整度是用来知道边界，不是用来全部学完。**

## 自己动手改

1. 在 `notes.md` 里写下你判断"智能体 vs 聊天机器人"的一句话标准。
2. 找一个你以前写过的后端定时任务（比如每天同步订单），用"五块拼图"的视角标一下：它哪块有、哪块缺？如果要让模型参与进来，你会加在哪一块？

## 坑

- **别一上来学 Harness（一键生成 agent 那类）**。它让你当天就能演示，但出问题你没有任何抓手。
- **别把"会调 API"当成"会做智能体"**。会调 API 只占第 2 块的一半，且是最简单的一半。
- **别急着上多智能体**。多数"多智能体需求"其实是"一个 agent + 几个工具 + 一条状态机"。
- **别把教程读完才动手**。每章都配了能跑的例子，读一章跑一个，交替推进。
