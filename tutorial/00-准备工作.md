# 第 00 章：准备工作

## 本章目标

1. 有一个能跑的 Python 环境（不污染你已有的项目）
2. 配好模型（Agnes 免费额度，零配置）
3. 确认一件最要命的事：**你用的模型会不会调用工具**

---

## 概念：为什么是 Python + uv

你不缺编程能力，缺的只是"这套工具链怎么用"。先给类比：

| 你在 web 里用的 | 这里对应的 | 作用 |
|---|---|---|
| `npm` / `composer` | **`uv`** | 装依赖、跑脚本。`uv add` ≈ `composer require` |
| `node_modules` | **`.venv`（虚拟环境）** | 每个项目一套依赖，互不干扰 |
| `package.json` | **`pyproject.toml`** | 项目定义与依赖清单 |
| `npm run dev` | **`uv run python xxx.py`** | 执行脚本 |

Python 没有 node_modules 那种自动隔离，所以"每个项目一个 `.venv`"是硬习惯。**别在你的主环境里装 langchain**——教程里的例子会频繁升级依赖。

## 跟着做

### 第 1 步：建独立环境

在**仓库根目录**建环境（`uv.lock` + `.venv` 都在这里），依赖清单已经写在 `pyproject.toml` 里了，所以只要一条命令：

```bash
uv sync
```

> 没有 `uv`？`pip install uv`。
>
> 为什么会有一个根目录的 `pyproject.toml`？因为教程里的命令写成 `uv run python examples/xxx.py`——
> **`uv run` 要能找到一个项目定义才会用对的环境**。没有它，`uv run` 会拿一个空环境去跑，
> 报出来的错是 `ModuleNotFoundError: No module named 'typing_extensions'`（跟 LangChain 毫无关系，
> 第一次遇到很难猜到原因）。这也是我实测撞到的。
>
> 它不会干扰 `virtual_rnd_center/`：uv 用的是**最近的** `pyproject.toml`，在那个目录里跑就用它自己的。

**为什么清单里有 `numpy`？** 它看上去跟智能体无关，但 `04_index_offline.py` 用的 `DeterministicFakeEmbedding`（假 embedding）内部要 `import numpy`，而 langchain-core 把 numpy 当成**可选**依赖没声明——不装它，你会在跟向量毫无关系的错误行上懵半天（实测报错：`NameError: name 'np' is not defined`）。

> ⚠️ **国内镜像可能装不上。** 实测清华镜像源对 `langchain` 包返回 `403 Forbidden`，uv 会报“langchain was not found in the package registry”（这句极具误导性——包明明存在，我一开始真去查了包名拼写）。
> 根目录的 `pyproject.toml` 已经显式指定官方源，所以你跑 `uv sync` 不会碰到这事。
> 你自己新建项目时如果遇到，把索引写进 `pyproject.toml`（比每次记 `--index-url` 靠谱，而且 `uv sync` 不认 `--index-url` 这个参数）：
>
> ```toml
> [[tool.uv.index]]
> name = "pypi"
> url = "https://pypi.org/simple"
> default = true
> ```

### 第 2 步：填 Key

```bash
cp examples/.env.example examples/.env
```

然后在 `examples/.env` 里填一行：

```
AGNES_API_KEY=sk-...
```

其它全部留空即可。示例代码里已经写好默认值：

| 项 | 默认值 |
|---|---|
| Base URL | `https://api.agnes-ai.cn/v1`（OpenAI 兼容，实测可用的地址） |
| 模型 | `agnes-2.5-flash`（2026-09-23 实测：普通调用 0.5s、工具调用 0.6s） |

换模型只改 `.env`：`MODEL=agnes-3.0-flash`。**不要改代码**——所有例子都从环境变量读配置，这是刻意设计的，你以后换成任何网关都只改一处。

> ⚠️ **两个实测到的网关侧问题**（2026-09-23，跟你的配置无关）：
> - `agnes-3.0-flash` 会出现**连接通、请求收下、然后一个字都不返回**（非流式/流式/带不带 `max_tokens` 全部 15s+ 超时，连测 4 次）。所以默认暂时用 `agnes-2.5-flash`。
> - `agnes-2.5-pro` 在免费额度下直接返回 **403（无权限）**——不是 Key 错。
> 遇到这两种，先换回 `MODEL=agnes-2.5-flash` 继续学，不要在这上面花时间。

### 第 3 步：自检（关键）

```bash
uv run python examples/00_env_check.py          # 只查环境
uv run python examples/00_env_check.py --live   # 真调一次模型
```

第二个命令会做两件事，其中第二件才是重点：

1. 普通调用一次，看能不能通
2. **让模型调用一个工具**，看它会不会调

你会看到类似这样：

```
✅ 会调用工具（2.3s）
   模型要求调用: get_time({'city': '上海'})
```

或者：

```
❌ 没有发起工具调用
   模型原话: 上海现在应该是上午十点左右...
```

## 看懂输出

**如果出现 ❌，先解决它再往下读。** 原因通常是这几种：

| 现象 | 原因 | 解决 |
|---|---|---|
| 模型"心算"而不调工具 | 这个模型工具调用能力弱 | 换 `MODEL=agnes-2.5-flash`（默认，实测会调） |
| **连接正常、但一直不返回**（光标干等，没有报错） | 网关侧那个模型当前不返回 | 换 `MODEL=agnes-2.5-flash`；实测 2026-09-23 的 `agnes-3.0-flash` 就是这个症状 |
| 跑几个例子后开始大面积报 `429` | 免费额度的**速率上限**（不是你写错了） | 歇一两分钟再跑（实测 20s 后恢复）；`run_all.py` 已内置自动重试 |
| 报 401 / 认证失败 | Key 不对、有空格、引号没去掉 | 检查 `.env` 里不要带引号 |
| 报模型不存在 | 模型名写错 | 只用文档列出的名字（`agnes-2.5-flash` 等） |
| 报 `403`（无权限） | 该模型要更高额度 | `agnes-2.5-pro` 免费额度不可用，用 `agnes-2.5-flash` |
| 连接超时 | 网络 / Base URL 写错 | 确认是 `https://api.agnes-ai.cn/v1` |

**为什么把这一步放在最前面？** 因为智能体的本质是"模型决定调用工具"。不会调工具，你后面写的每一个 agent 都会退化成"聊天机器人"，而你会以为是自己的代码写错了，白折腾几天。

## 自己动手改

1. 在 `.env` 里写一行 `MODEL=agnes-3.0-flash`，重跑 `--live`，比较两次的**耗时**和**工具调用参数**有什么不同。（如果它一直不返回——你刚刚亲手复现了下面排错表里的第三行。）
2. 故意把 `AGNES_API_KEY` 改错一个字符，看报错长什么样——**认识报错比认识正确用法更重要**。
3. 在 `examples/.env` 里加上 `LANGSMITH_TRACING=true`（和 `LANGSMITH_API_KEY`），第 02 章会用到。

## 坑

- **别把 `.env` 提交进仓库**。示例目录里已经有 `.gitignore` 习惯规范，你自己建项目时记得加。
- **别在示例里写死 Key**。你以后一定会把某个文件贴给别人看。
- **Windows 终端中文乱码**：示例已经内置处理（`_shared.setup_console()` 会把输出切到 UTF-8），你不用改代码。自己写脚本时如果乱码，先 `chcp 65001`，或设环境变量 `PYTHONIOENCODING=utf-8`。
  （实测不处理会直接崩：`UnicodeEncodeError: 'gbk' codec can't encode character '\u2705'`——报错位置跟你的逻辑毫无关系，很难猜。）
- **Python 版本**：建议 3.11 / 3.12。1.0 之后已放弃 3.9。
