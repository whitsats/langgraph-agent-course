# 第 19 章：附录 F —— 精读一个生产级 Agent 项目

> **可选**，约 1 周，**不进 5 周核心计划**（3 周最小路径直接跳过）。
> 全课唯一**没有自带例子**的附录：产出物是你自己的两份文件。

## F.0 这节补什么缺

本课的例子都是教学工程——为了让你看清一个概念，它们刻意省掉了生产系统里真正难的部分。
第 12 章结尾那份"它离生产还差什么"的清单（持久 checkpointer、评测、上限、Trace），
就是这些被省掉的东西的目录。

这份清单在**真实仓库里长什么样**，你还没见过。这一章不带读——**你自己去读一个
生产级项目**，但不是通读，也不是写读书笔记：用一套规格化的方法读，产出
**一份逆向规格（spec）+ 一份偏差清单**。读完你会得到两样东西：

1. 五条线上"生产级比教学级多做了什么"的具体答案（能落到文件、函数、参数级）
2. 一批可以直接抄进毕业项目的改进项（"值得学"清单）

**前置**：[第 12 章的"六问审阅法"](12-精读小项目.md)。精读时随身带着那六个问题，逆向规格化负责把答案变成文件。

## F.1 方法：逆向规格化（引自 SDD 课程 L11，这里只带十行版）

> 完整方法见 SDD 课程 L11「存量改造」：依据标注、偏差清单、变更热点。
> 本节只保留在"只读外部仓库"这个场景下**成立**的部分。

1. **按线读，不通读**。每次只读五条线（F.2）中的一条：入口文件 + 它的直接调用点。
2. 用 **EARS 句式**提炼这条线的验收标准："当 X 时，系统应 Y"。
3. 每条标准标注**依据**：`[code]`（从实现观察到的行为，附文件:行号）/
   `[test]`（有测试保护的）/ `[assumption]`（你的推断）/ `[suspicious]`（看着可疑的）。
4. `[assumption]` 必须**人工确认**后才算数；`[suspicious]` **永远不进规范**——
   它可能是有意设计，也可能是 bug，进规范就是把怀疑固化成纪律。
5. 逆向完成后过偏差：**它做的 vs 本课教的 vs 你以为的**，逐条归类：
   **它对 → 改我的规格（值得学）**／**它错 → 不改（教训）**／**取舍 → 记录双方理由**。
6. 不确定的东西进**"无法判定"小节**——假装判定比判错更危险。
7. spec 头部记录：被读仓库、**commit hash**、核查日期。你的 spec 从此锚定在这个快照上，
   上游仓库怎么变都不影响这份作业的可验证性。

**从 L11 里刻意弃用的三样**（照搬反而做不下去）：

| L11 的部件 | 为什么在这里弃用 |
|---|---|
| B 类偏差（规格写了、实现没有） | 外部仓库没有你预写的 spec 可对照——你的规格就是逆向出来的那份，B 类天然为空 |
| 变更热点排序 | 那是给"你接下来要改的仓库"定优先级的策略；你不打算改它，按五条线读，不按热点读 |
| 适配性判定 | "这个仓库适不适合 SDD"——你不接管它，判定没有对象 |

## F.2 精读范围：五条线

与第 12 章那份"离生产还差什么"清单对齐（Trace 并进线 4，向量库不设线——
第 08 章的五问决策法告诉你它经常不该上；新增了教学清单没有的"工具错误兜底"与"密钥"）：

| 线 | 读什么 | 本课对应 | 读后必答 |
|---|---|---|---|
| 1. checkpointer 与记忆 | 会话历史怎么管：截断、摘要、落盘 | 第 06 章、11b | 它比我 12 章小项目的 `InMemorySaver` + `history` 多做了什么？ |
| 2. 工具/动作错误的兜底 | 失败重试、反思、降级，各有几层 | 第 03、16 章 | 哪层兜底是代码、哪层是模型？静默失败藏在哪？ |
| 3. 并发与人工审批 | 谁在什么时候拦下动作等人点头；"超限"交给谁 | 第 07 章、10b | 它的"确认"是什么粒度？我的毕业项目该抄哪一档？ |
| 4. 评测与可观测 | 基准脚本、通过率、逐题记录、日志 | 第 11 章、17 章 | 它的评测集从哪来、多大规模？怎么防"感觉变好"？ |
| 5. 成本与密钥 | token 计量与展示；密钥怎么进系统 | 第 11 章（11d）、16 章 | 成本暴露给谁？密钥管理它做到了什么、**没做到什么**？ |

每条线的产出：3 条以上 EARS 验收标准 + 一段"它比我多做了什么"（具体到机制，不许写"它更健壮"）。

## F.3 选哪个仓库

### 遴选标准（每条附一行可执行的核查）

1. **工程上仍被真实用户大规模使用**——注意不是"最近提交频繁"：你要的是"做法没有过时到误导人"。核查：stars 数 + 你自己会不会真用它。
2. **代码库稳定**——读的这几周不会大改。核查：最后推送时间。几个月不动对只读精读反而是**好**属性：目标不会在你脚下移动。
3. **许可证允许**——核查：`gh api repos/OWNER/REPO --jq '.license.spdx_id'`；返回 `NOASSERTION` 就点进去读自定义条款（品牌条款、用户数限制都算坑）。
4. **规模 1–3 万行可读**（主包，不含前端和测试）——核查：`gh api repos/OWNER/REPO/languages`。
5. **技术栈与本课同构**（Python 优先）——一眼可辨，不同构一票否决。

### 候选快照（核查日期 2026-09-25，GitHub API 实测；标准比清单长寿，先跑核查再选）

| 候选 | 维护 | 许可证 | 规模 | 定位 |
|---|---|---|---|---|
| **Aider-AI/aider** | 放缓（2026-05 后无推送）但日活用户庞大 | Apache-2.0 | 主包 ≈1.9 万行（80 文件） | **主候选** |
| langchain-ai/react-agent（官方模板） | 活跃 | MIT | src ≈300 行 | 对照组（教学级） |
| langchain-ai/memory-agent（官方模板） | 活跃 | MIT | ≈300 行 | 对照组备选 |
| open-webui/open-webui | 活跃 | 自定义（品牌条款 + 50 用户限制） | 439 MB | 淘汰：许可证与规模 |
| danny-avila/LibreChat | 活跃 | MIT | TypeScript | 淘汰：不同构 |
| All-Hands-AI/OpenHands | 活跃 | MIT | 巨型 monorepo | 第二梯队：须强选择性阅读 |

### 主候选 aider：五条线入口地图（路径与大小已按 2026-09-25 的 main 分支核实）

主循环在 `aider/coders/base_coder.py`（≈2400 行）——**别从它开始通读**，从五条线切：

| 线 | 入口 | 看什么 |
|---|---|---|
| 1 记忆 | `aider/history.py`（≈150 行）、`aider/repomap.py` | 对话历史的摘要截断；repo map 怎么用有限 token 装下整个仓库的骨架 |
| 2 兜底 | `aider/coders/base_coder.py`、`aider/sendchat.py` | lint/test 失败后的反思重试；请求层的退避 |
| 3 审批 | `aider/io.py` | 每次编辑前的确认（ConfirmGroup）；对比第 07 章：交互 CLI 的确认 vs 图里的 `interrupt()` |
| 4 评测 | `benchmark/benchmark.py` | 一套生产评测脚本：逐题记录、通过率、成本——比你的 `eval.py` 多了什么 |
| 5 成本与密钥 | `aider/models.py`、`aider/commands.py`（`/tokens` `/cost`） | 逐会话 token 计费展示；密钥只走环境变量——"密钥管理外置"本身就是一条发现 |

一个值得专程去读的偏差素材：aider 做代码编辑**故意不用 function calling**（用编辑格式 + 反思）。
一个生产系统在什么约束下选了与本课第 04 章不同的路？把它写进偏差清单，归类"取舍"。

## F.4 交付物与验收

**交付物两份**：`specs/<仓库名>-<线>.md`（逆向规格）+ 偏差清单（三类 + 无法判定小节），
登记进规格台账。**五条硬验收**（勾完才算完）：

- [ ] **可复现锚点**：spec 头记录 仓库 / commit hash / 核查日期 / 各线入口文件。
      抽查任意 3 条 `[code]` 引用，在记录的 commit 上真实存在——验不过 = spec 是编的。
- [ ] **依据标注红线**：≥4 条线 × 每线 ≥3 条 EARS 标准，全部带 `[code]/[test]/[assumption]/[suspicious]`；
      `[assumption]` 全部经人工确认、`[suspicious]` 零入规范。
- [ ] **偏差清单不许"全绿"**：三分类零"待定"；且**至少 1 条被判"它也做错了"**——
      一份全是"值得学"的清单说明你在把源码当圣旨。
- [ ] **回链本课**：每条线一段"它比我多做了什么"，≥2 条到机制级；"值得学"条目
      ≥2 条转成毕业项目 backlog（九条硬要求之外的第 10 条就从这里来）。
- [ ] **台账 + 承认无知**：台账登记（owner = 你的人名、消费者 = 毕业项目、
      复审周期 = 毕业项目验收前一次）；**"无法判定"小节存在且非空**。

## F.5 对照组：官方模板半天读完

`langchain-ai/react-agent`（或 memory-agent）的 src 只有约 300 行，**半天读完**。
它是"本课教的写法 + 官方最佳实践"的教学级样本。读它的唯一目的，是给"它比我多做了什么"
提供一个**最小参照系**：同一个问题问两遍——生产项目比它多了什么、它比你的 12 章小项目多了什么。
两份答案的差集，就是"教学级 → 生产级"的那一段路。

## F.6 坑

- **把源码当圣旨**：偏差清单里全是"值得学"——你在做摘抄，不是精读。敢判"它也做错了"才说明读进去了。
- **忍不住通读**：五条线是围栏。主包 1.9 万行，通读一周下不来，而且主线读者根本不该走到这一章。
- **精读变搬运**：spec 里没有一个 `[assumption]`、没有一条"无法判定"——说明你只是把代码翻译成了散文。
- **把候选表当永久菜单**：那是 2026-09-25 的快照。先跑 F.3 的核查命令，再决定读谁。
- **在 5 周核心计划里手滑插进来**：它是毕业项目旁的可选扩展。"可选"的意思是：没时间就跳过，课程完整性不受影响。

## 验收问题

1. 为什么 `[assumption]` 不能直接采信、`[suspicious]` 不能进规范？（提示：把怀疑固化成纪律的代价）
2. "仍在活跃维护"这条标准为什么被拆成"真实用户规模 + 代码库稳定"两条？维护放缓对只读精读意味着什么？
3. 你的 spec 为什么必须记录 commit hash？没有它，三个月后这份 spec 还能验收吗？
4. 偏差清单的三分类里，哪一类最终会变成毕业项目的 backlog？走什么流程入账？
