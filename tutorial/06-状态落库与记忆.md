# 第 06 章：状态落库与记忆

## 本章目标

1. 亲手验证"状态真的落到了磁盘上"（**分两次运行**，中间把进程关掉）
2. 搞懂 `checkpointer` + `thread_id` 这一对概念，以及它替掉了你原本要自己搭的哪套东西
3. 知道从开发到生产该换哪个 checkpointer，以及四个生产必知
4. 分清**短期记忆（checkpointer）**和**长期记忆（Store）**，并跑通"跨会话记住同一个人"

**配套例子**：`examples/06a_persistence_resume.py`（离线）、`examples/06b_memory_agent.py`、`examples/06c_long_term_memory.py`（需要 Key）

---

## 概念：为什么"记住"是基础设施，不是模型能力

先破一个直觉：**模型本身不记得任何事**。你每次 `invoke` 都是全新的一次调用。所谓"记忆"，全是**你把历史再发一遍**。

那么"记忆"就是存储问题：

| 你以前的做法 | LangGraph 的做法 |
|---|---|
| 自己建 `sessions` 表，存聊天记录 | **checkpointer** 自动存**整个状态** |
| 用 `session_id` 区分用户 | **`thread_id`** |
| 用 Queue/Redis 做任务持久化 | checkpointer 让你**从断点继续跑** |
| 手写"上一步跑到哪了"的状态字段 | 每一轮都有可回放的 checkpoint |

**一句话**：checkpointer = 状态数据库。你把 `checkpointer` 参数挂上图，图就有了"内存"。

## 跟着做（核心实验：杀进程）

```bash
cd examples

uv run python 06a_persistence_resume.py first
# 现在把终端关掉（或者重启电脑，怎么折腾都行）
uv run python 06a_persistence_resume.py second
```

第二次的输出里最关键的是这一行：

```
  从数据库读到的状态: {'name': '小明', 'visits': 1}
  可以看到：这一次进程里从来没有设置过 name/visits，值是磁盘给的。
```

**为什么这个实验不可省略？** 因为"状态存住了"这件事，只在**新进程**里才能证明。同一进程里连续调两次，内存版和落盘版表现一样——你根本分不清。

代码上的三个点：

```python
with SqliteSaver.from_conn_string(str(DB_PATH)) as checkpointer:      # ① 用什么存
    graph = build_graph(checkpointer)

    config = {"configurable": {"thread_id": THREAD_ID}}               # ② 哪个会话
    graph.invoke({"name": "小明", "visits": 0}, config)               # ③ 第一次：传入初始状态

# 第二次运行时：
snapshot = graph.get_state(config)          # 读回来看看
graph.invoke({}, config)                    # ★ 传空 dict：不覆盖任何字段，直接用磁盘状态继续
```

**`invoke({})` 这一手非常关键**：传空字典表示"不给新输入，就用已有状态往下跑"。这就是"断点续跑"的字面意思。

---

## 概念：`thread_id` 就是 `session_id`

```python
config = {"configurable": {"thread_id": "customer-001"}}
```

你一定见过这个：**登录 session**。区别只在语义——`thread_id` 不只是"谁"，还是"哪条工作流实例"：

| 场景 | `thread_id` 怎么取 |
|---|---|
| 客服对话 | 用户 id 或 会话 id |
| 一个订单的审批流程 | `order-A-1`（订单号，天然唯一） |
| 一个项目的研发流程 | `project-2026-09` |

**多用户隔离原理就是这个**：不同 `thread_id`，状态物理隔离。示例 `06b` 会演示"换个 thread_id 立刻失忆"——那不是 bug，那正是你想要的。

## 概念：从开发到生产，只换一个类

| 后端 | 类 | 包 | 适合 |
|---|---|---|---|
| 内存 | `InMemorySaver` | 内置 | 开发、测试、单进程 |
| SQLite | `SqliteSaver` | `langgraph-checkpoint-sqlite` | 本地持久、单机小服务 |
| **Postgres** | `PostgresSaver` | `langgraph-checkpoint-postgres` | **生产首选**（异步版 `AsyncPostgresSaver`） |
| Mongo | `MongoDBSaver` | `langgraph-checkpoint-mongodb` | 已在用 Mongo 的团队 |
| Redis | `RedisSaver` | `langgraph-checkpoint-redis` | 高并发、短生命周期 |

```python
# 生产写法（业务代码一行都不用改）
from langgraph.checkpoint.postgres import PostgresSaver

with PostgresSaver.from_conn_string(DB_URI) as cp:
    cp.setup()                    # ★ 首次要建表
    agent = create_agent(..., checkpointer=cp)
```

### 四个生产必知

1. **首次必须 `setup()`**：它建表。忘了这步，报错信息不一定直白。
2. **`thread_id` 有长度限制**（列长 255）：别把 JSON 或超长路径塞进去当 id。
3. **checkpoint 会无限增长**：每轮都存一份，高频会话很快几个 G。**必须定期清理**（保留最近 N 轮 / 按时间清理）。
4. **不该落盘的字段用 `UntrackedValue` 排除**：数据库连接、大对象、密钥。否则状态文件里会躺着一堆没用的东西。

## 概念：短期记忆 vs 长期记忆（先把名字对齐）

checkpointer 只解决"这一个会话里聊了什么"。真实客服要的是"这个客人上次说过什么"——那是另一套东西，官方叫 **Store**。

| | 短期记忆 | 长期记忆 |
|---|---|---|
| 存在哪 | **checkpointer**（状态数据库） | **Store**（namespace + key + 语义检索） |
| 生命周期 | 一个 `thread_id` 之内 | 跨 thread、跨进程、跨设备 |
| 谁决定存什么 | 框架自动（整个状态都落盘） | **你自己**（写 `put` 的那一刻） |
| 回答的问题 | "我们刚才聊到哪了" | "这位客人有什么偏好" |

**一句话**：checkpointer 挂上去就有；Store 要你**设计**——记什么、记谁的、什么时候写、怎么删。

---

## 概念：长期记忆 = Store + namespace

```python
from langgraph.store.memory import InMemoryStore

store = InMemoryStore()                                        # 开发用；生产换持久后端
store.put(("memories", "user-001"), "fact-1", {"fact": "喝咖啡不加糖"})
store.get(("memories", "user-001"), "fact-1")                  # 按 key 取
store.search(("memories", "user-001"), query="口味", limit=3)   # 按语义找（要配了 index 才有语义）
```

三个要点：

1. **`namespace` 就是隔离键**：`("memories", user_id)`。它和 `thread_id` 不是一回事——**用稳定的用户 id / 项目 id，别用 thread_id**，否则换个会话就找不到了（那你就把长期记忆做成了短期记忆）。
2. **`search(query=...)` 的语义靠 `index` 配置**：`InMemoryStore(index={"dims": 64, "embed": ...})`。
   ⚠️ **实测细节**：不配 `index` 时 `search(query=...)` **不会报错**，它退化成"按插入顺序列出来"（返回项的 `score` 是 `None`）——也就是说**你以为在做语义检索，其实没有**。这种静默降级比报错危险，所以要用真 embedding 的话，务必先把 `index` 配好。练习期可以先塞假 embedding 把链路跑通（跟 RAG 是同一条供应链）。
3. **`InMemoryStore` 重启即丢**，只适合开发。生产换持久化 Store（官方 Memory 页列了各后端与安装包）。

### 怎么让 agent 用上它（agent 侧只有一个参数）

```python
from langchain.agents import AgentState, create_agent
from langchain.tools import ToolRuntime, tool

@tool
def remember(fact: str, runtime: ToolRuntime[None, AgentState]) -> str:
    """记住关于当前用户的一条事实。"""
    user_id = runtime.config["configurable"]["user_id"]      # 稳定的用户 id
    runtime.store.put(("memories", user_id), "fact-1", {"fact": fact})
    return "已记住。"

agent = create_agent(
    model=..., tools=[remember, recall],
    checkpointer=InMemorySaver(),   # 短期：thread 内
    store=store,                    # ★ 长期：工具里通过 runtime.store 拿到
)
agent.invoke(..., {"configurable": {"thread_id": "chat-001", "user_id": "user-001"}})
```

⚠️ **实测坑**：运行时注入的参数必须写成带泛型的 **`ToolRuntime[None, AgentState]`**。裸写 `ToolRuntime` 会被当成普通参数去做 schema，报一条跟记忆毫无关系的错：

```
TypeError: BaseModel.__init__() takes 1 positional argument but 2 were given
```

**写完自检一行**：`print(remember.args)` 里不应该出现 `runtime`——出现了就说明泛型标注漏了。

### 三型记忆 + 两种管理方式（照抄这个框架，业务里就不会乱）

| 记忆类型 | 存什么 | 例子 |
|---|---|---|
| **Semantic**（语义） | 事实 | "这位客人对花生过敏" |
| **Episodic**（情景） | 经历 | "上周他退过一次单" |
| **Procedural**（程序） | 规则 / 指令 | 这位 VIP 的专属话术、agent 的系统提示词 |

写入时机两选：**热路径**（agent 回答前自己决定"这条要记"）或**后台任务**（对话结束后异步总结记忆）。召回形态两选：**Profile**（每个用户一份持续更新的 JSON，简单但会越写越大）或 **Collection**（一条条事实，召回好、但更新和删除要自己管）。

**别一上来就"自动记住一切"。**先回答三个问题：**记什么类型**、**谁决定写**、**写坏了怎么删**。答不上来就先做最保守的那版：只记关键事实 + 热路径写入 + 给用户一个"清空记忆"的入口。

## 看懂输出

`06a` 例子最后一行：

```
  历史 checkpoint 数量: 3      # 具体数字取决于你跑了几次，重点是这个数在涨
```

**这个数字比状态更能说明问题**：每次状态变化都留了一份快照。它带来两个能力（第 07 章会用到）：

- **回放**：`graph.get_state_history(config)` 拿到所有历史快照，看流程在每一步长什么样
- **分叉**：`graph.update_state(config, 新值)` 从某个历史点开一条新路

⚠️ **注意**：`update_state` **不是回滚**，它是"从某点分叉出新 checkpoint"。旧的还在。这是新手最容易误解的地方。

## 坑

- **有 checkpointer 但不传 `thread_id`**：直接报错，且报错信息要你加 `configurable`。
- **以为历史会自己清理**：不会。不做清理策略，数据库会被 checkpoint 吃满。
- **把大对象放进状态**：每次快照都会复制一份。用 `UntrackedValue` 排除。
- **拿 `thread_id` 存超长字符串**：列长限制是 255。
- **在节点里写副作用**：有了持久化 + 重跑，副作用会重复执行（第 07 章会具体演示）。
- **忘了 `setup()`**：Postgres 版第一次跑必踩。
- **用 `InMemoryStore` 当生产记忆**：进程一重启，所有用户"集体失忆"。
- **namespace 里塞 `thread_id`**：跨会话失效，正好和长期记忆的目的相反。
- **`ToolRuntime` 漏写泛型**：报 `TypeError: BaseModel.__init__() takes 1 positional argument but 2 were given`。
- **长期记忆没有删除入口**：用户说"忘掉我"时你只能干瞪眼。**存之前先想好怎么删。**
